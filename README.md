# 8051 Dino Game

**C / 8051 Assembly · Preemptive Multithreading · SDCC · EdSim51**

在 8051 平台上實作的雙列小恐龍避障遊戲。玩家透過矩陣鍵盤選擇難度，
並控制恐龍在 LCD 的上下兩列移動，避開由右向左移動的仙人掌；
碰撞後顯示 Game Over 與累計分數。

本專案以互動遊戲串接微控制器上的輸入、計算與顯示流程。
實作重點包含 Timer 0 搶佔式執行緒切換、共享佇列同步、
位元地圖，以及 LCD 自訂字元與局部更新。

## 專案重點

| 技術面向 | 實作方式 |
| --- | --- |
| 執行緒排程 | Timer 0 中斷進行執行緒切換，並提供 ThreadYield 主動讓出 CPU |
| 輸入處理 | 掃描矩陣鍵盤，將按鍵事件寫入容量為 3 的環狀佇列 |
| 執行緒同步 | 使用 mutex、full、empty 信號量管理佇列；部分共享狀態以短暫關閉中斷保護 |
| 地圖表示 | 兩個 16-bit 整數表示 2 × 16 個位置，障礙物地圖本身使用 4 bytes |
| LCD 顯示 | 以 CGRAM 儲存恐龍與仙人掌字元，依更新旗標選擇全地圖或角色欄位更新 |

這裡的 4 bytes 僅指障礙物地圖，不是整個遊戲或執行緒系統的 RAM 用量。

## 遊戲操作

| 按鍵／操作 | 功能 |
| --- | --- |
| `0`～`9` | 在開始畫面選擇難度；數字越大，地圖更新門檻越低 |
| `#` | 開始遊戲 |
| `2` | 將恐龍移到上列 |
| `8` | 將恐龍移到下列 |
| 重設並重新執行模擬 | 回到初始畫面，開始新的一局 |

恐龍固定在畫面最左側，透過上下換列避障，而不是使用重力與跳躍軌跡。
按鍵輸入會記錄按下狀態；釋放後再次按下，才會產生下一次事件。

目前程式只以 `#` 處理開始操作。
初始提示字串雖包含 `*`，但它沒有對應的開始功能。
遊戲結束後也沒有內建重新開始按鍵。

## 系統架構

### 三個長駐執行緒

| 執行緒 | 職責 |
| --- | --- |
| `Keypad_Ctrl` | 掃描按鍵、辨識新的按下事件，並寫入輸入佇列 |
| `Game_Ctrl` | 讀取輸入、管理遊戲狀態、移動障礙物、碰撞判定與計分 |
| `Render_Task` | 載入自訂字元，依遊戲狀態與更新旗標輸出 LCD 畫面 |

初始化時建立鍵盤與遊戲控制執行緒，原本的主執行緒則進入顯示工作。
三者共享同一個 CPU，透過排程交錯執行，並非三個核心同時運算。

輸入流程為：

    矩陣鍵盤 → Keypad_Ctrl → 環狀佇列 → Game_Ctrl
                                             ↓
                                         遊戲狀態
                                             ↓
                                        Render_Task → LCD

執行緒核心位於 [preemptive.c](firmware/preemptive.c)。
切換時保存與還原 ACC、B、DPTR、PSW 及 R0～R7，
並為各執行緒記錄堆疊指標。

### 遊戲狀態與位元地圖

遊戲採用三個狀態：

| `state` | 行為 |
| --- | --- |
| `0` | 選擇難度並等待開始 |
| `1` | 處理移動、障礙物、碰撞與計分 |
| `2` | 顯示結束訊息與分數 |

地圖由 `map[0]` 與 `map[1]` 表示上下兩列。
每個 bit 對應一個 LCD 欄位，最低位對應恐龍所在的最左欄：

```c
map[0] >>= 1;
map[1] >>= 1;

if (map[dino_row] & 1) {
    state = 2;
}
```

障礙物從最高位 `0x8000` 加入，並在每四次地圖更新後產生一次。
生成列由分數的奇偶決定，不是隨機生成。

難度控制地圖更新的迴圈計數門檻：

```c
gc_shift_timer > (10 - difficulty) * 15
```

這是遊戲控制執行緒的迴圈計數，不是以毫秒定義的固定週期。
實際顯示速度還會受到執行緒排程與模擬設定影響。

### LCD 更新

恐龍與仙人掌以兩組 8-byte 點陣寫入 LCD 的 CGRAM，
分別使用自訂字元編號 1 與 2。

`render_flag` 區分兩種更新：

- `0x01`：更新選單、完整地圖或結束畫面。
- `0x02`：只更新恐龍所在的第一欄，避免角色換列時重畫整張地圖。

顯示完整地圖前，程式會在短暫關閉中斷的區段中複製地圖與角色位置。
此做法用於取得部分共享資料的快照，不代表已完成所有競態情況的驗證。

主要遊戲邏輯與顯示流程位於 [dino.c](firmware/dino.c)。

## 建置與執行

### 工具

- SDCC：編譯 C 與內嵌 8051 組合語言。
- GNU Make：執行隨附 Makefile。
- EdSim51：載入編譯結果並操作模擬周邊。

SDCC 與 Make 需要可由命令列執行。
本專案不使用桌面電腦的 GCC 直接建置。

### 編譯遊戲

在專案根目錄執行：

```sh
cd firmware
make
```

Makefile 使用 `sdcc -c --model-small` 編譯各模組，
再連結產生 `dino.hex`。

請使用 Makefile 的檔案清單，不要一次將所有 `.c` 連結在一起：
`dino.c` 與 `testlcd.c` 是兩個不同程式，各自具有入口與中斷轉接函式。

### 在 EdSim51 中執行

開啟 EdSim51，以 Load 載入 `firmware/dino.hex`，
選擇 Intel HEX 檔案類型，再執行模擬。

確認 LCD 與 keypad 的接腳配置符合程式。
若曾使用動態周邊配置功能，需核對設定，不能只確認程式成功載入。

先選擇難度，再按 `#`，使用 `2` 與 `8` 避障。

### 周邊輸入展示程式

[testlcd.c](firmware/testlcd.c) 是獨立的周邊輸入展示：
兩個 producer 分別讀取按鈕列與矩陣鍵盤，
consumer 從共享佇列取出字元並寫入 LCD。

它保留在倉庫中供閱讀與延伸測試，不會被預設的遊戲建置目標編入。

## 接腳與模組

以下為原始碼所使用的配置，不代表已驗證任意實體開發板的接線。

| 周邊 | 程式中的接腳 |
| --- | --- |
| LCD DB7～DB4 | `P1.7`～`P1.4` |
| LCD RS | `P1.3` |
| LCD E | `P1.2` |
| 矩陣鍵盤掃描 | `P0` |
| 鍵盤初始化中的輸入設定 | `P3.3` |
| 按鈕列，供周邊展示使用 | `P2` |

LCD 驅動使用 4-bit 傳輸。
`LCD_ready()` 回傳的是軟體維護的狀態旗標，
不是讀取 LCD 控制器的硬體 busy flag。

接腳與周邊程式可分別參閱
[lcdlib.c](firmware/lcdlib.c)、
[keylib.c](firmware/keylib.c)、
[buttonlib.c](firmware/buttonlib.c)。

## 驗證範圍與限制

原始開發紀錄包含 EdSim51 的選單、遊戲中與結束畫面。
本整理版本保留原始程式及 Makefile，未重新編譯或重跑模擬，
也沒有宣稱已在實體 8051 開發板上完成測試。

目前採用固定記憶體配置與三個長駐執行緒，
沒有提供完整的動態執行緒結束及資源回收機制。
更動編譯器、函式呼叫深度或執行緒配置時，需要重新檢查記憶體與堆疊使用。

遊戲結束畫面顯示分數的三位十進位數字；
目前不包含暫停、持久化最高分與遊戲內重新開始功能。
